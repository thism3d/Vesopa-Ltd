## 1. Licensing (Nicky's two Newbridge videos, 4 Nov)

Newbridge console: Company > Site > Terminal, with an access key, version and last
ping per terminal, and about 40 settings categories per terminal, each row editable
with Copy To Terminal. Written up in the plan.

What we have today:

| Piece | State |
|---|---|
| Seats (`till_seats.js`) | Limits per venue, one seat per machine |
| Licence keys (`bo_licence_keys`) | Optional, bound to a hardware fingerprint, but typed AS WELL AS a sign-in |
| Till token | 10 years (`TERMINAL_TOKEN_TTL`) |
| Kitchen and display tokens | 90 days, so they do ask again |
| Venue till settings | Back office (`epos_till_settings`), per venue, not per terminal |
| Terminal settings (printers and so on) | On the machine: 33 files in `vesopa_epos/lib` use local storage, so a reinstall can lose them |

Gaps to close:

- A terminal licensed by venue code, terminal number and access key, with no email or password.
- Kitchen screens and displays stop expiring at 90 days.
- A per-terminal settings document in the back office, pulled at start, pushed on change.
- Company > Site > Terminal pages in back office and admin: number, name, version, last ping, pending updates, Copy to terminal.
- Same for Go, kitchen, display and kiosk.
